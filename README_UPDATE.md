# تحديث phase-90 — إصلاح إشعارات Android عبر FCM

> الإصدار الحالي `phase-90` — كاش الخدمة `laqino-v134`. تحديث إضافي فوق phase-89؛ لا يغيّر دورة الطلبات أو Web Push.

## ما اتصلح
- جسر Capacitor لا يعلن اكتمال التهيئة قبل توفر إضافة Push Notifications، ويحاول تسجيل الإضافة الأصلية عند الحاجة.
- طلب صلاحية الإشعارات وتسجيل FCM يبدأان بعد وجود جلسة دخول، مع إعادة المحاولة عند تعذر التسجيل أو تجديد توكن الجهاز.
- تحميل الجسر مع ملف شرح الأذونات في الرئيسية وصفحة التسجيل ولوحة المندوب والسوق والصيدلية ولوحة المحل وصفحة استعراض المحلات.
- توجيه إشعارات المحادثات والتوصيل والطبي ومنتجات الصيدلية وطلبات المحلات إلى صفحاتها المناسبة.
- إضافة إشعار خارجي لمالك المحل عند إنشاء طلب عميل، دون استبدال إشعار المندوب.
- إضافة وجهة داخلية اختيارية إلى بيانات FCM مع السماح بمسارات داخلية محددة فقط، ومنها فتح تبويب طلبات المحل مباشرة.
- إضافة إشعار خارجي للصيدليات عند وصول استفسار دواء جديد في نطاقها، مع استهداف الصيدليات المعتمدة فقط.

## حدود التحقق
- اختبارات GitHub Actions قيد التشغيل؛ لا يُعتمد التحديث قبل مراجعة نتائجها.
- لم يُبنَ APK ولم يُختبر وصول FCM على جهاز حقيقي.
- مشروع Android/AndroidManifest غير متتبع داخل مستودع Laqino؛ يلزم إضافة `POST_NOTIFICATIONS` في مشروع Capacitor نفسه قبل بناء APK.
- يلزم التأكد من تفعيل `LAQINO_FCM_SERVICE_ACCOUNT` على السيرفر من `/api/admin/fcm/status`.

## سجل التحديث السابق — phase-88

> الإصدار السابق `phase-88` — كاش الخدمة `laqino-v132` (السابق `laqino-v131`). تحديث إضافي فوق phase-87؛ لا يغيّر تدفقات الطلبات أو وظائف الحساب القائمة.

## ما اتصلح
- صفحة «حسابي» لم تعد تنتظر تحميل `/my/applications` و`/owner/shops` قبل العرض؛ تُحمّل البيانات في الخلفية وتحدّث اللوحات عند وصولها.
- `/delivery/orders` و`/my/listings` يُحمّلان بالتوازي في الخلفية. بعد 650ms كحد أقصى تظهر واجهة الحساب مع حالة تحميل واضحة، ثم تُعرض الطلبات والإعلانات فور وصول البيانات.
- أُلغي التحديث الكامل غير المشروط كل 8 ثوانٍ، والذي كان يعيد تحميل الحساب والإعلانات والطلبات واللوحات حتى دون وجود تغيير. تحديث التوصيل الحي لم يُلغَ: بقي `tick()` لمقارنة حالة الطلبات وتحديث الصفحة عند تغيّرها.
- أُضيفت فهارس SQLite تراكمية لاستعلام طلبات العميل، وإعلاناته، وأحداث الطلبات؛ لا حذف ولا تعديل للسجلات الموجودة.
- أضيف حارس ترتيب للتنقل حتى لا تستبدل استجابة قديمة صفحةً أحدث بعد انتقال المستخدم بين الأقسام.

## الملفات
`static/index.html`, `server.py`, `static/sw.js`, `VERSION`, `README.md`, `PROJECT_STATE.md`, `STATUS.md`, `README_UPDATE.md`, `test_phase88_account_loading.py`.

## التحقق
أضيف `test_phase88_account_loading.py` لفحوص عدم رجوع التحديث الدوري، وبقاء تتبع الطلبات، والتحميل الخلفي، والفهارس. لم يُشغّل الاختبار أو اختبار المتصفح في هذه المراجعة؛ يلزم التحقق بعد تشغيل فحوص المشروع والنشر.

# تحديث phase-87 — الطلب المباشر من الصيدلية (قسم المنتجات) + إصلاح بث الإشعارات

> الإصدار السابق `phase-87` — كاش الخدمة `laqino-v130`. التحديث فوق phase-86 (تفاصيل م5 في `README_UPDATE_PHASE86.md`).

## 1) اطلب من الصيدلية مباشرة ← يتحول دليفري
- العميل في «المنتجات» (أو صفحة الصيدلية): زر **«اطلب من الصيدلية»** على كل منتج ← شريط سلة ← ورقة الطلب (كميات + عنوان + ملاحظة) ← «ابعت الطلب للصيدلية». سلة صيدلية واحدة في كل مرة.
- الطلب يوصل الصيدلية «جديد» (إشعار جرس + Push). **لا يُرسَل مندوب قبل ما الصيدلية تقبل.**
- الصيدلية (لوحتها ← الطلبات ← «طلبات المنتجات»): **قبول** ← يتحول فورًا لطلب توصيل عادي (`origin_type=product_order`) ويبحث له النظام عن مندوب ← **جاهز للاستلام**، أو **اعتذار** (قبل القبول أو بعده وقبل استلام المندوب؛ بعد القبول يُلغى الدليفري).
- العميل في «حسابي ← طلباتي»: قبل الرد كارت «بانتظار رد الصيدلية» (مع إلغاء)، وبعد القبول قايمة المراحل والفاتورة (أصناف + أجرة + إجمالي) واسم/رقم المندوب. الأجرة يقترحها المندوب ويوافق عليها العميل كباقي الطلبات.
- الأسعار لقطة وقت الطلب. الصيدلية لا ترى عنوان/هاتف العميل. ثمن المنتجات يُحاسَب بين العميل والصيدلية.
- الشرط: مفتاح المنتجات `products_enabled` شغّال، وأجرة منطقة الصيدلية مضبوطة.
- سقوف: 5 طلبات «جديدة» معلّقة، 10 طلبات/ساعة، 20 صنف، كمية حتى 20.

## 2) إصلاح الإشعارات
- شات السوق كان يُشعر الطرف الآخر فقط (جُرّب بـ5 مشتركين). لكن السيرفر كان يبعث Push لكل مشتركي التطبيق عند كل إعادة تشغيل (`push_resume`)؛ صار للمناديب المعتمدين فقط.

## الملفات
جديد: `product_orders.py`، `test_phase87_product_orders.py`. معدّل: `server.py`، `fcm.py`، `VERSION`، `static/index.html`، `pharmacy.html`، `courier.html`، `app.css`، `sw.js`، `test_phase30_push_resume.py`.
