# phase-56 (تراكمي فوق phase-55) — الإصدار `phase-56`، كاش `laqino-v91`

1. **اختيار الصيدلية الصريح بلا حالة لكل صنف** (النظام الجديد) (`rx.py` POST `/quote` + `static/pharmacy.html`): زرّين «الروشتة كاملة ← إرسال» (`send_mode=full`) و«تم إرسال المتاح وسيتم توفير الناقص» (`send_mode=partial`). الصيدلية تكتب **المتاح فقط** (اسم + كمية + سعر) والاختيار هو اللي يحدد: `full` = الرد اكتمل ويقفل البحث، `partial` = متاح بس ويُعاد توزيع الروشتة كلها. مفيش حالة متاح/غير متاح/يحتاج تأكيد لكل صنف، وعدد الأصناف المكتوبة هو مقياس أفضل رد جزئي (`best_partial`). الاكتمال لكل صيدلية لوحدها (لا تجميع بين الصيدليات، ولا «أصناف متوقعة» تُستنتج من رد الصيدلية). الواجهات القديمة (حالة لكل بند + `confirm_all`) لسه شغالة. بحث الأصناف الفرعي يحتفظ بنطاقه: `full` = كل أصنافه، `partial` = مجموعة جزئية منها.
2. **إخفاء الردود الجزئية عن العميل** (`customer_quotes` في `rx.py`): في وضع التوزيع التلقائي الجزئي يتحفظ ولا يظهر ولا إشعار «وصلك رد» أثناء البحث؛ في النهاية يظهر أفضل رد جزئي فقط (مع الرد الكامل ومن قُبل جزئيًا ومن له توصيل). الإشعار للرد الكامل فقط.
3. **إعادة توزيع الروشتة كلها** (`rx.py`: `advance_claim_after_review` و`_claim_next` و`_offer_all`): بعد رد جزئي الصيدلية التالية تسعّر الروشتة كلها بدل الأصناف الناقصة فقط، ولا نطاق `rx_claim_items` يُكتب أو يبقى قديمًا. بحث الأصناف الفرعي (`kind='item'`) يحتفظ بنطاقه. الاكتمال ما زال يُحسب بتجميع التغطية (بند 5 مفتوح).

4. **بحث الصنف الناقص بالكتابة أو بالصورة** (`/missing-search` في `rx.py` + `rxMissing` في `static/index.html`): العميل يكتب اسم الصنف (وكميته) بإيده أو يرفع صورته فقط (أو الاتنين)، ويشتغل بنفس نظام الروشتات: عروض لكل الصيدليات، أول قبول يحجز 10 دقايق، ومهلة كلية. مفيش اشتراط قايمة «أصناف ناقصة» من الصيدلية. رد «كاملة» على الفرعي بيكمّل الأصل. الصورة بدون اسم بتتوزع بلا نطاق أصناف. زر «إرسال لصيدلية أخرى» (`/remaining`) شغال وبيوزّع الروشتة كلها.
