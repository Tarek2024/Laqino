# المرحلة 6ب — تقييم مقدمي الخدمات

## 1. القرارات
- **نجوم فقط (1–5)، بلا نص حر**: لا حاجة لإشراف على تعليقات مسيئة، ولا تُكشف هوية المقيِّم.
- من يقيّم: صاحب الطلب فقط، بعد أن يصبح الطلب `done` وقد قبله مقدم خدمة. تقييم واحد لكل طلب (UNIQUE).
- العرض: المتوسط (رقم عشري واحد) والعدد علنيان في بطاقة المقدم وتفاصيله؛ المقدم يراهما في «شغل الخدمات»؛ الإدارة في «ربط مقدمي الخدمة».
- **منع التقييم الذاتي:** المقدم لا يقبل طلبًا صادرًا من حسابه (403)، وطلب أغلقته الإدارة دون مقدم لا يُقيَّم.

## 2. ما أُنجز
- جدول `service_ratings` (إضافة فقط، `CREATE IF NOT EXISTS`)، و`POST /api/service-requests/<id>/rate {stars}`.
- حقلا `rating_avg`/`rating_count` في `GET /api/services` و`/api/services/<id>` (تعديل سطرين في `svc_row` بـ`server.py`)، وحقلا `rated`/`can_rate` في طلبات العميل.
- إشعار لصاحب حساب المقدم عند وصول تقييم.
- الواجهات: قائمة نجوم وزر «قيّم المقدم» في طلبات العميل، شارة ★ في بطاقة المقدم، متوسط في لوحة المقدم والإدارة. كاش v38.

## 4. لم يُنفَّذ / لم يُجرَّب
- لا تعديل للتقييم ولا حذفه (من العميل أو الإدارة)، ولا فرز المقدمين بالتقييم، ولا حد أدنى للعدد قبل إظهار المتوسط.
- التقييم يظهر في قائمة الخدمات وتفاصيلها فقط، لا في نتائج البحث العام (`gsearch.py`).
- الواجهات فُحصت نصيًا وبفحص صياغة JS، دون Chromium أو هاتف أو Termux أو Docker.
