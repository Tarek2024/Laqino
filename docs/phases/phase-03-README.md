## 3. ما أُنجز فعليًا (كان موجودًا قبلها: رفع صورة ← تحويل الإدارة لصيدلية واحدة ← رد بحالة وسعر واحد ← طلب توصيل)
- وحدة جديدة `rx.py` (بنمط `products.py`، لا تستورد `server.py`) + جدول جديد `rx_quote_items` (إضافة فقط).
- **تسعيرة ببنود (صيدلية):** `POST /api/provider/prescriptions/<id>/quote` بقائمة بنود `{name, qty, unit_price, available}`. الإجمالي يُحسب في الخادم ويُكتب في `prescription_responses.price`، فيبقى طلب التوصيل والإشعارات القائمة كما هي. كل البنود متوفرة ← `available`؛ بعضها ← `needs_confirmation` (جزئي، بسعر المتوفر)؛ لا شيء ← `unavailable`. `GET` على نفس المسار يرجع بنود الصيدلية لتعبئة النموذج.
- **مقارنة الأسعار (عميل):** `GET /api/medical/prescriptions/<id>/quotes`: كاملة وحديثة (الأرخص أولًا) ← كاملة قديمة ← جزئية ← الباقي. علامة `cheapest` على أرخص تسعيرة كاملة وحديثة، و`fresh` حسب `stock_fresh_hours`، و`missing` بأسماء البنود غير المتوفرة. بلا هواتف.
- **إغلاق الروشتة (عميل):** `POST /api/medical/prescriptions/<id>/close` يغلقها ويسحب صلاحية الصيدليات، **عدا** الصيدلية التي لها طلب توصيل غير ملغي (تحتاج الروشتة لتجهيز الطلب).
- **تحويل متعدد (إدارة):** `POST /api/admin/prescriptions/<id>/forward-many` بـ `{provider_ids:[..]}` (حتى 10) أو `{auto:true}` (صيدليات المنطقة وأسلافها وأحفادها، حتى 8). يتجاهل غير المعتمدة، ومكرّر الاستدعاء آمن.
- **تحويل تلقائي عند الرفع:** مفتاح `rx_auto_forward` (**مغلق افتراضيًا**: التفعيل قرار الإدارة) عبر `GET|POST /api/admin/rx/auto-forward` (التعديل للأدمن فقط). `server.py` يستدعي `rx.auto_forward` بعد إنشاء الروشتة؛ وأي خطأ فيه لا يُفشل الإنشاء.
- **صلاحية الروشتة:** لا تقبل تسعيرات بعد 14 يومًا (`settings.rx_expire_days` اختياري) ← 409.
- **الإشعارات:** لم يلزم شيء جديد؛ triggers `ntf_` القائمة تُنبّه الصيدلية عند التحويل والعميل عند ورود رد (اختُبر).
- **الواجهات:** `pharmacy.html` نموذج بنود (إضافة بند، متوفر/غير متوفر، تعبئة مسبقة من تسعيرتها السابقة)؛ `index.html` بطاقة مقارنة (الأرخص، البنود، الإجمالي، تنبيه «قديم»، زر طلب التوصيل للكاملة الحديثة فقط) وزر «إغلاق الروشتة»؛ `admin.html` اختيار عدة صيدليات + «تحويل لصيدليات المنطقة» + مفتاح التحويل التلقائي. كاش `v32`.

## 4. القواعد
- طلب التوصيل يبقى كما هو في `server.py`: يشترط رد `available` حديثًا (≤ `stock_fresh_hours`). التسعيرة الجزئية لا تُفتح لها توصيلة.
- بنود: 1–30، الاسم 2–80 حرفًا، الكمية 1–99، سعر الوحدة (0، 100000]، الإجمالي ≤ 1,000,000.
- لاقينو لا تحصّل ثمن الدواء ولا تقترح بدائل أو جرعات (كما في الواجهة القائمة).

## 7. لم يُنفَّذ / لم يُجرَّب
- لم يُجرَّب على متصفح/هاتف حقيقي ولا Docker ولا Termux. الواجهات الثلاث عُدّلت وفحصت **نصيًا فقط** (لا fake-DOM لها في هذه المرحلة) وتحتاج تجربة يدوية، خصوصًا نموذج البنود وإضافة صفوف.
- **صورة واحدة فقط للروشتة** (كما كان): دعم عدة صور يحتاج تعديل فحص الصلاحية في `GET /api/files/<id>`.
- لا تكرار لتسعير بنود الروشتة تلقائيًا (OCR) ولا ربط ببيانات `provider_stock`؛ الصيدلية تكتب البنود بنفسها.
- قائمة الإدارة تعرض الروشتات `pending` فقط، فالروشتة التي حُوِّلت لصيدلية لا تظهر لتحويلها لصيدليات إضافية من الواجهة (الـ API يسمح).
- لا زر إلغاء/استرجاع لطلب التوصيل من شاشة المقارنة (يتم من «طلباتي»).
