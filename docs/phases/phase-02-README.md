# المرحلة 2 — القسم الطبي وعروض المنتجات (مكتملة بعد الدفعة 2ب)

## 1. الرقم والاسم والهدف
المرحلة 2: `laqino-phase-02-medical-products`. الهدف: صيدلية معتمدة تنشر عروض منتجات غير دوائية (تجميل، أم وطفل، عناية شخصية، مستلزمات طبية) بعد مراجعة الإدارة، ويتصفحها العميل ويبحث فيها.

## 2. الأساس
الأساس: `Laqino-last-version.zip` (`a5d7b5b0bc1ade76`) + المرحلة 1 + `laqino-phase-01b-listing-link.zip` (كاش v29). هذا الـ ZIP يحوي الملفات المعدّلة كاملة فقط.

## 3. ما أُنجز فعليًا
- وحدة جديدة `products.py` (بنمط `notif.py`، لا تستورد `server.py`) + جدول جديد `product_offers` (إضافة فقط، `CREATE IF NOT EXISTS`، لا ترحيل).
- **العميل:** تبويب «المنتجات» داخل الخدمات الطبية (بحث + فلتر تصنيف + «عرض المزيد»)، وقسم «المنتجات» في البحث الشامل.
- **الصيدلية (`pharmacy.html`):** نموذج إضافة منتج، قائمة عروضها بحالتها وسبب الرفض، تأكيد/تعديل السعر، تبديل متوفر/غير متوفر، حذف.
- **الإدارة (`admin.html`):** تبويب «منتجات الصيدليات» (نشر/رفض بسبب) وزر «إنشاء التصنيفات الافتراضية».
- التصنيفات الأربعة (مستحضرات تجميل، الأم والطفل، عناية شخصية، مستلزمات طبية) تحت جذر «الطبي»؛ **تُنشأ بضغطة من الإدارة** (لا تلقائيًا، لأن مبدأ المشروع أن التفعيل قرار الإدارة وهذا ما تفترضه اختبارات `test_phase2`/`test_setup_initial`). بدونها لا يستطيع أحد النشر.
- `/api/search` صار يرجع مفتاح `products`.

## 3ب. دفعة الإكمال (2ب) — `laqino-phase-02b-products-complete.zip`
- **صور المنتجات:** حتى 3 صور للعرض. تُرفع عبر مسار `/api/listings/images` القائم (نفس سقف 40 صورة للمستخدم، JPG/PNG، تُجرَّد بياناتها الوصفية)، ثم تُمرَّر `image_file_ids` عند إنشاء/تعديل العرض. جدول جديد `product_images`. تغيير الصور يعيد العرض للمراجعة، والصور المزالة تُحذف من القرص، وحذف العرض يحذف صوره. الصورة عامة للعرض المنشور فقط (`GET /api/medical/products/<id>/images/<fid>`)، وغير ذلك لصاحبها والإدارة. `/api/files/<id>/delete` يرفض حذف صورة مرتبطة بعرض (409).
- **إشعارات (triggers بادئة `ntf_prod_`):** للإدارة عند عرض جديد/معدَّل بانتظار المراجعة (رابط `admin:products`)، ولصاحبة العرض عند النشر/الرفض. تُحذف مع `notif.uninstall`. عُدّل `test_notifications.py` ليستثني هذه الثلاثة من عدّ triggers الإشعارات الأصلية.
- **صفحة عامة للصيدلية:** `GET /api/medical/pharmacies/<id>` (اسم/منطقة/عنوان + عروضها المنشورة، بلا هاتف، 404 لغير المعتمدة). في الواجهة: اسم الصيدلية في بطاقة المنتج وبطاقة الصيدلية في نتائج البحث يفتحانها. `/api/search` يرجع `id` للصيدليات.
- الاختبارات: `test_phase2_products.py` صار 71 فحصًا؛ الانحدار 60 ملفًا exit 0.

## 4. القواعد
- يظهر للعميل فقط: معتمد + متوفر + صيدلية معتمدة + تصنيف ظاهر + **آخر تأكيد خلال 14 يومًا** (`settings.product_fresh_days` اختياري)، وبنفس منطق المنطقة للصيدليات (المنطقة وأسلافها وأحفادها). بلا منطقة = كل المناطق.
- تعديل الاسم/الماركة/الوصف/التصنيف يعيد العرض للمراجعة؛ تعديل السعر/التوفر/التأكيد لا يعيدها.
- الحد 200 عرض لكل صيدلية، السعر > 0 وحتى مليون، السعر القديم أكبر من الحالي. لا أي رقم هاتف في أي رد عام.
- تحذير تشغيلي: لا يوجد فحص آلي يمنع صيدلية من كتابة اسم دواء كمنتج؛ **مراجعة الإدارة هي الضابط الوحيد**.

## 5. API
عام: `GET /api/medical/product-categories?region_id=`، `GET /api/medical/products?q=&category_id=&region_id=&limit=&offset=` → `{items,total}`.
صيدلية معتمدة: `GET|POST /api/provider/products`، `POST /api/provider/products/<id>/(edit|confirm|delete)`.
إدارة/موظف: `GET /api/admin/products?status=`، `POST /api/admin/products/<id>/review` `{status,reason}`، `POST /api/admin/products/seed-categories`.
